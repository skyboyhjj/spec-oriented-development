模板 B · 实现自检清单 —— 实际例子：古版·竖排

功能实现后逐条对照规约的自检结果（真实勾选）。

数据与模型

  • ☑ 无新增数据模型（纯展示增强），不涉及字段一致性

规约与边界

  • ☑ 用户主权（第七/十一条）：切换偏好存 localStorage，不上传服务器

可回退与可维护

  • ☑ 新功能为独立外挂模块，可单独停用
  • ☑ 未修改不必要的既有代码
  • ☑ 代码注释显式回指规约条款号（如「用户主权(第7条)→localStorage」）

验证与复现

  • ☑ 验收标准逐条实测：默认激活 ✅ 繁体正确 ✅ 右到左多列 ✅

模板 C · 项目记忆 —— 实际例子：project_memory.md 真实摘录

直接摘录 daodejing-kb 的 project_memory.md，展示「硬约束 / 约定 / 教训」三栏的真实写法。

## Hard Constraints（硬约束 · 不可违反）
- 古版竖排功能采用纯外挂实现，不修改章节核心代码，可随时回退
- 古版竖排与今文横排切换状态通过 localStorage 持久化，不依赖服务端存储
- 人机结合策略审计方案严格遵循「人主机辅」原则：AI 仅「提出+探测」生成候选策略，
  「整合/固化」必须由人类导师审阅后手工落地，禁止自动写入 System Prompt 或 Skill
- 策略审计端点为只读设计，请求数据用完即弃不落库，响应强制附加「不会自动生效」免责声明

## Engineering Conventions（工程约定 · 默认遵循）
- 古版竖排优先使用繁体楷体复古字体栈（Kaiti TC / TW-Kai / DFKai-SB），回退简体楷体
- 简繁转换仅在古版竖排视图生效，今文横排保持原文简体不变
- 繁体配对数据 js/s2t-data.js 自动生成；改原文后须 `npm run s2t:check` 复查
- 部署遵循「Vercel 先行灰度验证 → 同步 Cloudflare Pages 生产入口」的分级发布流程
- 新增功能 MVP 按「B 路径（本地化存储）先行 → C 路径（飞书持久化）」顺序推进

## Lessons Learned（经验教训 · 避坑）
- 竖排布局窄屏横向溢出，需单列滑动 + 固定高度 + overflow-x:auto，避免双方向滚动
- GitHub 推送首次常遇网络重置错误，重试一次即可成功
- 子代理 browser_use 存在网络访问限制，验证站点可用性需用 curl 直连而非依赖子代理结果

模板 D · 偏差记录 —— 实际例子：SkillUP（成长模型）12 处偏差

来源：AGENTS.md「已知偏差案例」+ docs/SkillUP_水德四阶段_执行规格_v2.0.md「十、相对 v1.0 的修正项」。 「后果/影响」为对照宪法与设计原则做的偏差影响分析，「修正动作」为 v2.0 已落地的修复。

# 偏差项 规约要求（设计） 实际实现（早期） 后果 / 影响 修正动作（v2.0）
1 成长模型隐喻 「水德」：水滴→溪流→江河→江海 「植物」：萌芽→小苗→树木→森林 与宪法隐喻体系不符，用户对成长的认知割裂 改回水德四阶段
2 阶段阈值 阅读章节 10 / 30 / 60 3 / 10 / 30 成长节奏判定偏差，用户过早被「升级」 改回 10/30/60，并附加认知深度 + 提问条件
3 触发规则 4 条（阅8章 / 切L3 / 连续3天 / 主动查询） 仅 2 条（数字里程碑 + 主动查询） 缺失关键成长反馈时机，陪伴感减弱 补全 4 条规则
4 连续天数 真正连续检测（断一天即清零） 首次至今总天数差 「坚持天数」虚高，违背坦诚透明原则 calcConsecutiveDays 实现真正连续检测
5 独立许可文件 skillup-consent.js 独立文件 内嵌于 skillup-ui.js 许可逻辑与 UI 耦合，违背外挂增强、难维护 拆出独立 skillup-consent.js
6 数据模型 keyword 字段 questions 含关键词提取 无 keyword 无法提炼核心概念，「常问概念」缺失 CORE_KEYWORDS + extractKeyword
7 数据模型 chapter 关联 questions 关联章节 messages 无 chapter 字段 提问无法关联到具体章节，成长画像失真 questions[].chapter 字段
8 数据模型 chaptersVisited 数组 string[] 对象 {} 数据结构不一致，迁移与统计成本升高 chaptersVisited: string[]
9 章节页面底部引导 章节页底部提供学习引导 未实现 缺少章节学习闭环，用户读完即走 getChapterGuidance 实现
10 CSS 视觉效果 设计系统禁用 blur / box-shadow 实现了 backdrop-filter: blur + box-shadow 违反水墨道风设计系统，视觉风格漂移 修正为水墨道风约束
11 lastVisit 字段 设计有 lastVisit 实现用 firstVisit 字段语义错误，无法反映「最近访问」 lastVisit 字段已存在
12 totalChaptersRead 独立计数字段 动态计算 与规格不一致，埋下迁移隐患 独立计数 + 动态同步

偏差记录的价值：这 12 处不是「改掉就完了」，而是被永久写进 AGENTS.md 作为反面教材——让下一个会话（哪怕换了模型、换了上下文）接手时，能直接看到「曾经偏离过什么、为什么错、正确做法是什么」，从而不重蹈覆辙。这正是「偏差即教材」的意义。

小结：四个模板如何串成闭环

需求 → [模板 A] 转译成规约条款 → 实现 → [模板 B] 对照规约自检
                                        │
                            发现偏差 ↓ [模板 D] 记成反面教材
                                        │
                    每次会话结束 ↓ [模板 C] 沉淀进项目记忆
                                        │
                        下次会话从「记忆 + 偏差案例」继续，不再重新踩坑

一句话原则：先有规约，再写代码；实现回指规约，验证对照规约，经验反哺规约。
