# 面向规约开发（Spec-Oriented Development）

> 让 AI 协作从「一次性聪明」走向「可复用约束」
> 案例来源：《道德经》知识库项目（daodejing-kb）「古版·竖排」功能的完整复盘

---

## 一、为什么需要「面向规约」

长期与 AI 结对开发，会撞上三个反复出现的痛点：

1. **跨会话漂移** —— 换一个上下文、换一次模型，AI 就忘了之前的约定，同样的功能写出不一样的风格。
2. **伦理漂移** —— 功能越做越「花哨」，渐渐偏离最初的价值观边界，没人说得清当初为什么这么定。
3. **经验不沉淀** —— 一次性解决了一个难题（比如某个二义字的处理），下次遇到还得从头推理一遍。

「面向规约」的回答是：**不依赖 AI 的「自觉」，而是依赖一套可被机器和人共同遵守的规约**，让 AI 始终在明确的边界内稳定产出。

---

## 二、规约的四个层级

规约不是一份文档，而是**从抽象到具体、层层落实**的四层体系：

| 层级 | 是什么 | 回答的问题 | 载体示例 |
|:---|:---|:---|:---|
| **① 宪法** | 价值观与伦理边界 | 为什么做、边界在哪 | 最高产品宪法（用户主权、减法优先、坦诚透明、外挂增强等条款） |
| **② 设计文档** | 具体功能的规格 | 做成什么样 | 数据模型、阈值、状态机、命名 |
| **③ 工程约定** | 技术实现约束 | 怎么做 | AGENTS.md（外挂增强、零服务端、设计 tokens、命名规范、代码模式） |
| **④ 项目记忆** | 跨会话沉淀 | 踩过什么坑、定了什么决策 | Hard Constraints / Conventions / Lessons Learned |

关键点：**每一层都是上一层的具体化**。宪法说「用户主权」，设计文档就要写「可切换 + 记住用户选择」，工程约定就要写「localStorage 持久化」，代码里再落到 `localStorage.setItem(...)`。四层之间可以一路追溯。

---

## 三、五步闭环

这是可复用的核心工作流：

1. **需求即转译** —— 拿到需求先问「要满足哪几条规约」，不急着写代码。
2. **实现即对齐** —— 每个设计决策回指规约条款号，代码注释显式标注「为什么这么写」。
3. **验证即自检** —— 用固定清单逐条对照规约，而不是只看「功能能不能跑」。
4. **经验即固化** —— 把一次性聪明固化为脚本 / 流程 / 约定，让「复查」变成「按规约执行」。
5. **偏差即教材** —— 把偏离规约的实现记成反面案例，供下一个会话避坑。

## 四、案例复盘：古版·竖排的完整过程

### 全流程时间线

| 阶段 | 关键动作 | 规约如何起作用 |
|:---|:---|:---|
| **① 需求提出** | 最初想做古籍竖排 PDF，后转向 web 版竖排展示，先做第一章 demo | 需求先被翻译成「要满足哪几条宪法」，而非直接写代码 |
| **② 伦理对齐** | 做减法优先 / 坦诚透明 / 用户主权三项整改 | 每条改动回指宪法条款号，代码注释显式标注 |
| **③ 繁体与字体** | 竖排转繁体 + 复古楷体字体栈 | 二义字「语境定字」经验被固化，而非停留在口头 |
| **④ 规约沉淀** | 复查流程写入 AGENTS.md，建 PROJECT_CONTEXT / README | 一次性经验变成可复现的约定与命令 |
| **⑤ 运营验证** | 双平台部署 + 本地复验三项功能 | 验证按「默认激活 / 繁体正确 / 右到左多列」逐条自检 |

### 三个最能体现「规约」力量的细节

**细节一：代码注释直接标注条款映射**

```javascript
/* 伦理对齐（慧惠·伦理即道体）：
   用户主权(第7条) → localStorage 记住选择，不强制
   减法优先(第5条) → 默认回归原文古版；切换控件弱存在感
   坦诚透明(第9条) → 底本 / 异文 / AI辅助 显性标注
   外挂增强(第10条) → 不改动 .original-text 内部结构，运行时叠加 */
```

代码本身成了「为什么这么写」的证据链，任何人（或任何 AI）读代码都能追溯到规约条款。

**细节二：一次性经验固化为三模式脚本**

简繁转换有个隐蔽难点：二义字要按语境定字（「云」说义不转「雲」、「谷」山谷不转「穀」但「不谷」谦称转「不穀」）。这个经验没有停留在对话里，而是固化为：

- 一个生成脚本（含按语境定字的映射表）
- 一个同形字白名单快照
- 三条命令：`s2t:check`（检查新增字）/ `s2t:accept`（接受同形字）/ `s2t`（重新生成）

此后任何人改原文，只需「按规约复查」，不需要重新推理整个简繁逻辑。

**细节三：工程约束直接消除一类 bug**

AGENTS.md 里有一条约定「新增功能优先外挂增强，最小化修改核心代码」。古版竖排因此做成一个纯外挂模块（新 JS + 新 CSS），不碰章节核心代码，可随时回退。这既守住了「减法优先」，又天然降低了回归风险。

---

## 五、收益

- **一致性**：跨会话、跨模型，产出风格稳定，边界清晰。
- **可追溯**：任何一行代码都能回指到「为什么这么写」的规约条款。
- **可复现**：复查、纠偏、返工都有既定流程，不再依赖个人记忆。
- **可传承**：经验随规约沉淀，新人（或新 AI）接手上手成本低。

---

## 六、如何上手

1. 先写 **宪法**（3～8 条价值观/边界即可，别贪多）。
2. 为当前要做的功能写一份 **设计文档**（数据模型 + 阈值 + 命名 + 状态机）。
3. 建一份 **AGENTS.md** 约定（技术约束 + 代码模式 + 复查清单）。
4. 每个会话结束，把结论写入 **项目记忆**（Hard Constraints / Conventions / Lessons Learned）。
5. 配套一份 **可复用模板**（见姊妹篇《面向规约开发 · 可复用模板》）。

> 原则：**先有规约，再写代码；实现回指规约，验证对照规约，经验反哺规约。**
