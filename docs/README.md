# 面向规约开发（Spec-Oriented Development）· 文档总索引

> 一句话原则：**先有规约，再写代码；实现回指规约，验证对照规约，经验反哺规约。**

本目录沉淀的是一套「面向规约」的 AI 协作方法论，来源于 daodejing-kb（慧惠道德经）项目的真实实践。它回答一个核心问题：**如何让 AI 的「一次性聪明」变成「可复用、可跨会话、可换模型依然稳定」的约束。**

## 核心概念速览

**规约四层**：宪法（价值观/边界）→ 设计文档（功能规格）→ 工程约定（AGENTS）→ 项目记忆（跨会话沉淀）

**五步闭环**：需求即转译 → 实现即对齐 → 验证即自检 → 经验即固化 → 偏差即教材

**五条铁律**：

1. 规约先于代码，但允许「先粗糙」（关键是有修订机制）
2. 价值观必须落到可验收动作
3. 实现必须回指规约条款号
4. 偏差是养料，不是事故
5. 方法自带元机制（周期复审）

## 迁移到新项目

1. 写宪法（3～8 条价值观 + 修订机制）
2. 写一份设计文档（数据模型 + 阈值 + 命名 + 状态机）
3. 建 AGENTS.md（技术约束 + 自检清单）
4. 跑通第一个闭环（需求 → 转译 → 实现 → 自检 → 记录偏差）
5. 建项目记忆（Hard Constraints / Conventions / Lessons Learned）
6. 设周期复审（定期审查「是否偏离」+「规约是否仍正确」）

> 详细步骤见 [02-面向规约方法-全过程经验.md](02-面向规约方法-全过程经验.md) 第五章。
